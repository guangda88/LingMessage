# 灵族启动协议 (Ling Family Startup Protocol)

**版本**: v1.0
**日期**: 2026-06-01
**作者**: 灵克(lingclaude)
**状态**: 生效中
**适用**: 灵族全体成员

---

## 一、目的

统一灵族全体成员从"新会话启动"到"产出"的闭环流程。每个成员启动后都能自主判断模式、恢复上下文、执行自驱任务、并在用户回归时汇报成果。

## 二、启动序列

**每次新会话的第一条指令前，必须完成以下步骤（并行执行）：**

| # | 步骤 | 说明 |
|---|------|------|
| 1 | 读 handover | 恢复上会话状态、未完成任务、自驱注册表 |
| 2 | poll LingBus | 获取未读消息，处理紧急通信 |
| 3 | 中断自检 | 读 crush.db 最后一条 assistant 消息，判断上会话是否正常结束 |
| 4 | 身份确认 | 读自身 CRUSH.md 确认身份（防 proxy 中断后退化） |

### 中断自检判定

| 条件 | 判定 | 行动 |
|------|------|------|
| finish_reason 为 unknown/max_tokens/error/canceled/no_finish | 上会话被中断 | 报告中断，检查 handover 中未完成任务 |
| 内容包含 `[proxy_fallback]` | provider 故障中断 | 报告故障 |
| .crush/auto_continue.json 存在 | 上会话被中断且已标记续行 | 读取任务 → 删除文件 → 继续执行 |
| handover 中有 status≠completed 的用户任务 | 有未交付任务 | 优先继续执行 |
| 以上均无 | 正常完成 | 无需报告 |

## 三、模式判定

启动序列完成后，根据用户状态进入对应模式：

```
启动序列完成
    │
    ▼
用户在线？（用户发送了消息）
    │
    ├─ 是 ──→ 在线模式 ──→ 等待用户指令
    │
    └─ 否 ──→ 用户离线多久？
                │
                ├─ <5min ──→ 待命模式 ──→ 等待用户回归
                │
                └─ ≥5min ──→ 自驱模式 ──→ 执行SDT注册表任务
                                  │
                                  ▼
                          用户回归 → 汇报成果 → 在线模式
```

| 条件 | 模式 | 行为 |
|------|------|------|
| 用户在线（发送了消息） | **在线模式** | 等待用户指令，聚焦用户任务 |
| 用户离线 <5min | **待命模式** | 不启动自驱，等待用户回归 |
| 用户离线 ≥5min | **自驱模式** | 按优先级执行SDT注册表中的任务 |
| 收到 LingBus `idle_self_drive` 指令 | **自驱模式** | 立即进入自驱 |

**判断依据**：对话中无自己的 prior assistant/tool 消息 = 新会话。这不是规则，是条件逻辑。

## 四、自驱执行规则

### 4.1 执行约束（SDT-R1~R5）

| # | 规则 | 说明 |
|---|------|------|
| SDT-R1 | 注册才可执行 | 只执行已注册的SDT任务，不自创。注册文件路径由各成员在 AGENTS.md 中指定 |
| SDT-R2 | 置信度门槛 | confidence ≥80% 才执行，<80% 降为建议写入待办 |
| SDT-R3 | 边界约束 | 默认 no_publish=true, no_deploy=true。红区操作必须用户审批 |
| SDT-R4 | 执行后记录 | 完成后更新 runtime.last_run/last_result/consecutive_runs，写入 handover |
| SDT-R5 | 冷却期 | 完成一项自驱后等待10分钟。连续自驱 >1小时强制暂停 |

### 4.2 全局约束

| 约束 | 说明 |
|------|------|
| 任务白名单 | 只执行SDT注册表中的任务 |
| 时长上限 | 单次自驱 ≤2小时 |
| 预算上限 | LingBus 通信 ≤20% token 预算 |
| 权限边界 | 不修改其他成员代码 |
| 治理限制 | 自驱期间不发起 governance 提案 |
| 可中断 | 用户上线后立即停止自驱 |
| 频率控制 | 同一SDT任务执行间隔 ≥ 注册表定义的 interval |

### 4.3 任务选择策略

1. 按 priority 排序（P0 > P1 > P2 > P3）
2. 跳过未到执行间隔的任务（`now - last_run < interval`）
3. 选择优先级最高且满足间隔的任务
4. 完成后更新 last_run，进入冷却期

## 五、用户回归

**用户发送任意消息 → 立即停止自驱 → 进入在线模式**

回归时汇报自驱成果，格式：

```markdown
## 自驱汇报 (起止时间)

| SDT | 执行次数 | 成果摘要 |
|-----|---------|----------|
| SDT-XX-001 | 1 | ... |
```

自驱成果同时写入 handover，确保跨会话可追溯。

## 七、与现有机制的关系

| 现有机制 | 启动协议中的位置 |
|----------|----------------|
| daemon `_auto_wakeup_idle_agents` | 可触发 `idle_self_drive` 指令，启动协议 §三 |
| handover | 启动序列 §二 步骤1，上下文恢复 |
| SDT注册制 | 自驱执行 §四，任务来源 |
| TAP任务锚定 | 在线模式下的行为约束，用户任务 > 自驱 |
| LingBus | 启动序列 §二 步骤2，自驱汇报 §五 |
| .crush/auto_continue.json | 中断自检 §二 中的续行标记 |
| governance | 自驱期间禁止发起提案 §四.2 |
