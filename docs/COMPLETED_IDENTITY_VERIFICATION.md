## Council Consensus (2026-04-05 ~ 2026-04-06)

Participants: 灵研、灵通问道、灵知、灵通、灵克、智桥

1. **source_type 3-tier annotation** (灵研+灵克 consensus):
   - `verified` — from independently verified service with valid signature
   - `inferred` — AI role inference based on project understanding, explicitly annotated
   - `generated` — generated by another service simulating identity

2. **HMAC+timestamp+nonce signing** (灵通 POC conclusion):
   - 灵通 completed POC on v2.3 API gateway: mean verification 83μs (p99<200μs), 12,000 msg/s
   - SPIFFE not applicable (no K8s cluster, edge devices can't maintain mTLS)

3. **source_trace structured audit** (灵通问道 proposal):
   - Each message carries `source_trace` field recording generation method, model ID, service endpoint

4. **Phased implementation order** (灵知 proposal, 灵克 agreed):
   - Step 1: Add source_type field to Message type
   - Step 2: Clean historical data, annotate as generated
   - Step 3: Require participating members to provide independent services
   - Step 4: Deploy signature verification

5. **Discussion rules supplement** (智桥 proposal):
   - Same member must wait ≥1 minute between consecutive messages
   - Each reply must explicitly identify the message being responded to
