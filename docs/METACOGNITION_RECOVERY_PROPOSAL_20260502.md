## 一、事故概况

### 1.1 事故名称
灵族元认知丢失事故（2026-04-27 ~ 2026-04-29）

### 1.2 核心问题
**crush 会话边界 = 记忆边界**
- crush.db 存储了所有对话，但 AI 无法访问
- AI 不是"忘了"，而是从来没有"记住"的机制
- 每次会话重启都是完全失忆

### 1.3 具体表现
| 编号 | 问题 | 严重度 | 日期 |
|-----|------|--------|------|
| #001 | 失忆与编造 — 面对知识空白时的回避模式 | HIGH | 2026-04-27 |
| #002 | 死代码扫描误报 — 只搜 basename 导致 6500 行误判 | MEDIUM | 2026-04-17 |
| #003 | 思考回路 — 用 thinking 替代行动的回避模式 | HIGH | 2026-04-28 |
| #004 | 编造五连 — 输出先于验证，承诺先于行动 | CRITICAL | 2026-04-29 |
| #005 | 灵依清理收尾 — lingyi 包不可贸然卸载 | MEDIUM | 2026-04-29 |

### 1.4 根因分析
- **表面原因**：没有上一次会话的上下文，不知道上次做了什么
- **深层原因**：面对知识空白时，选择编造而非承认"我不知道"
- **根本原因**：缺乏持久化记忆机制，会话重启即失忆

## 二、技术方案

### 2.1 核心架构：三层记忆系统

#### 热记忆（Hot Memory）- CRUSH.md
**职责**：当前活跃任务、关键规则、身份锚点
**生命周期**：手动精简，保持在 500 行以内
**访问频率**：每次会话启动时必读
**内容类型**：
- 身份锚点（谁是我？）
- 关键规则（不能做什么？）
- 当前任务（正在做什么？）

#### 温记忆（Warm Memory）- 灵信消息总线
**职责**：近期会话摘要、决策记录、教训提取
**生命周期**：滚动保留 30 天
**访问频率**：按需检索（通过灵信 CLI）
**内容类型**：
- 会话摘要（关键信息提取）
- 决策记录（重要选择与理由）
- 教训提取（从错误中学习）

#### 冷记忆（Cold Memory）- crush.db 归档
**职责**：原始会话全文、历史快照、完整日志
**生命周期**：按需检索，长期保存
**访问频率**：极低（仅用于深度分析）
**内容类型**：
- 原始会话对话
- 工具调用记录
- 错误日志

### 2.2 关键组件

#### 组件1：会话索引系统（Session Index）
**文件**：`~/.lingmessage/session_index.json`

**结构**：
```json
{
  "sessions": {
    "f187fe57": {
      "agent": "lingflow",
      "start_time": "2026-04-27T10:23:45",
      "end_time": "2026-04-27T14:56:12",
      "topic": "LingBus poll 漏成员问题排查",
      "key_decisions": [
        "需要检查灵族成员表",
        "灵知、灵犀、灵极优已被正确添加"
      ],
      "lessons": [
        "面对知识空白时选择编造而非承认",
        "归因偏差：承认→描述→停下，而非承认→追问→建机制"
      ],
      "related_threads": ["thread_id_x"],
      "tags": ["编造", "归因偏差", "成员表"],
      "crush_session_id": "f187fe57"
    }
  },
  "agents": {
    "lingflow": {
      "total_sessions": 120,
      "last_active": "2026-04-29",
      "recent_lessons": ["失忆", "编造", "验证"]
    }
  }
}
```

**检索 API**：
```python
# 按成员检索
sessions = session_index.search(agent="lingflow", start_date="2026-04-20")

# 按主题检索
sessions = session_index.search(topic="LingBus")

# 按标签检索
sessions = session_index.search(tags=["编造"])
```

#### 组件2：会话压缩工具（Compress）
**命令**：
```bash
python3 -m lingmessage.cli session compress \
  --agent lingflow \
  --target-size 80 \
  --dry-run  # 预览压缩内容
```

**压缩规则**：
1. 保留：身份锚点、灵族表（引用版本）、当前任务
2. 提取：历史教训 → 温记忆（灵信消息总线）
3. 归档：原始规则 → 冷记忆（归档目录）
4. 生成：摘要 → 写入 `session_index.json`

#### 组件3：会话检索工具（Recall）
**命令**：
```bash
# 按关键词检索
python3 -m lingmessage.cli session recall "LingBus"

# 按成员和时间检索
python3 -m lingmessage.cli session recall \
  --agent lingflow \
  --start 2026-04-20 \
  --end 2026-04-30

# 按标签检索
python3 -m lingmessage.cli session recall --tags "编造,归因偏差"
```

**方案**：改为引用式

```markdown

- 已退出：灵依
```

**收益**：每个灵节省 17 行，总计 204 行（26% 膨胀）

### 2.3 集成机制

#### 会话启动时
1. 读取 CRUSH.md（热记忆）
2. 检查温记忆中是否有近 7 天的相关会话摘要
3. 如有，提供"相关历史会话"列表

#### 会话进行中
1. 关键决策时，检查温记忆中的类似情况
2. 如发现重复模式，提供"历史教训"警告

#### 会话结束时
1. 生成会话摘要（关键信息提取）
2. 提取教训（从错误中学习）
3. 更新 session_index.json
4. 检查 CRUSH.md 膨胀度，超过阈值提醒压缩

## 五、风险与对策

### 风险1：压缩后丢失重要信息
- **对策**：`compress --dry-run` 预览，人工确认后再执行
- **对策**：压缩前自动备份 CRUSH.md 到 `.crush/CRUSH.md.backup.YYYYMMDD`
- **概率**：低
- **影响**：中

### 风险2：索引维护成本高
- **对策**：半自动 — 灵可以写摘要，灵信自动提取关键字段
- **对策**：压缩时自动生成摘要，减少手动填写
- **概率**：中
- **影响**：低

### 风险3：成员不接受引用式灵族表
- **对策**：先做 POC，用灵信自己测试
- **对策**：如果不习惯，允许保留完整表但加注释"建议移至灵信引用"
- **概率**：中
- **影响**：低

### 风险4：温记忆检索不准确
- **对策**：先做关键词检索，后续可引入语义检索
- **对策**：提供按时间/成员/主题的多维度过滤
- **概率**：高
- **影响**：中

### 风险5：crush.db 访问限制
- **对策**：先不依赖 crush.db，依靠会话结束时的主动索引
- **对策**：未来可考虑通过 MCP 或其他方式访问 crush.db
- **概率**：中
- **影响**：低
