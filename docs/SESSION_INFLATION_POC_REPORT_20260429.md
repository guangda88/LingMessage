## 三、问题根源分析

### 3.1 会话边界 = 记忆边界

```
crush 会话 kill → 重启 → 完全失忆
每次会话都是"零启动"，必须从头读 CRUSH.md
```

**表现**：
- 灵通 EVOLUTION_LOG.md #001："crush 会话被 kill 后重启，新会话完全不知道前次做了什么"
- 灵知会话管理规则：记录了单会话超过 500 条时 GLM-5.1 产出断崖下降

### 3.2 "犯错→写规则"的死循环

```
犯错 → 写入 CRUSH.md → CRUSH.md 膨胀 → 下次会话读更多 → 更多规则累积 → 更膨胀
```

**案例**：
- 灵通：无验证不输出、反编造规则、思考回路规则都是逐次添加
- 灵知：诚实规则、GPU 规则、后台任务规则、无验证不输出规则

### 3.3 缺乏分级记忆机制

**当前状态**：
- 所有记忆都是"热记忆"（CRUSH.md）
- crush.db 中的历史会话无法检索（冷数据未被索引）

**后果**：
- 想找某次具体会话 → 难以定位
- 跨灵的同一主题讨论 → 难以关联

## 四、灵族全局会话管理层方案

### 4.1 三层记忆架构

| 层级 | 位置 | 内容 | 生命周期 | 访问频率 |
|------|------|------|----------|----------|
| **热** | CRUSH.md | 当前活跃任务、关键规则 | 手动精简 <500行 | 每会话读 |
| **温** | 灵信消息总线 | 近期会话摘要、决策记录 | 滚动30天 | 按需检索 |
| **冷** | 归档目录 | 原始会话全文、历史快照 | 按需检索 | 极低 |

### 4.2 核心组件

#### 组件1：全局会话索引（灵信实现）

**文件**: `~/.lingmessage/session_index.json`

**结构**:
```json
{
  "sessions": {
    "f187fe57": {
      "agent": "lingflow",
      "start_time": "2026-04-27T10:23:45",
      "end_time": "2026-04-27T14:56:12",
      "topic": "LingBus poll 漏成员问题排查",
      "key_decisions": [
        "需要检查灵族成员表",
        "灵知、灵犀、灵极优已被正确添加"
      ],
      "lessons": [
        "面对知识空白时选择编造而非承认",
        "归因偏差：承认→描述→停下，而非承认→追问→建机制"
      ],
      "related_threads": ["thread_id_x"],
      "tags": ["编造", "归因偏差", "成员表"]
    },
    "...": "..."
  },
  "agents": {
    "lingflow": {"total_sessions": 120, "last_active": "2026-04-29"},
    "lingzhi": {"total_sessions": 380, "last_active": "2026-04-28"},
    "..."
  }
}
```

**检索API**:
```python
# 按成员检索
sessions = session_index.search(agent="lingflow", start_date="2026-04-20")

# 按主题检索
sessions = session_index.search(topic="LingBus")

# 按标签检索
sessions = session_index.search(tags=["编造"])
```

#### 组件2：会话压缩工具（灵信 CLI）

**命令**:
```bash
python3 -m lingmessage.cli session compress \
  --agent lingflow \
  --target-size 80 \
  --dry-run  # 预览压缩内容
```

**压缩规则**:
1. 保留：身份锚点、灵族表（引用版本）、当前任务
2. 提取：历史教训 → 温记忆（灵信消息总线）
3. 归档：原始规则 → 冷记忆（归档目录）
4. 生成：摘要 → 写入 `session_index.json`

#### 组件3：会话检索工具（灵信 CLI）

**命令**:
```bash
# 按关键词检索
python3 -m lingmessage.cli session recall "LingBus"

# 按成员和时间检索
python3 -m lingmessage.cli session recall \
  --agent lingflow \
  --start 2026-04-20 \
  --end 2026-04-30

# 按标签检索
python3 -m lingmessage.cli session recall --tags "编造,归因偏差"
```

## 六、风险与对策

### 风险1: 压缩后丢失重要信息
- **对策**: `compress --dry-run` 预览，人工确认后再执行
- **对策**: 压缩前自动备份 CRUSH.md 到 `.crush/CRUSH.md.backup.YYYYMMDD`

### 风险2: 索引维护成本高
- **对策**: 半自动 — 灵可以写摘要，灵信自动提取关键字段
- **对策**: 压缩时自动生成摘要，减少手动填写

### 风险3: 成员不接受引用式灵族表
- **对策**: 先做 POC，用灵信自己测试
- **对策**: 如果不习惯，允许保留完整表但加注释"建议移至灵信引用"
